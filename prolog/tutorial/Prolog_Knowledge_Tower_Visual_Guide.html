그림으로 보는 Prolog

사실 하나가 트리가 되고,
질의 하나가 그 트리를 훑는다

지금까지 코드와 텍스트로 설명한 것을 ACRUX-2의 실제 System–Subsystem–Component 계층 위에 그려서 다시 봅니다. 굵은 선이 "지금 이 규칙이 실제로 훑고 있는 경로"이고, 옅은 선은 "존재하지만 이번 질문과는 무관한 부분"입니다.

§1

사실(Fact) — 계층 구조 그 자체

아래 그림이 facts_model.pl(또는 cubesat.pl)에 적힌 consists_of/2 사실 12줄 전부입니다.

선 하나하나가 사실 한 줄입니다. acrux2 → adcs 화살표는 consists_of(acrux2, adcs).라는 문장 그 자체예요. 코드와 그림 사이에 번역이 필요 없다는 게 Prolog의 특징입니다 — 그림을 코드로 옮기면 정확히 아래와 같습니다. 

% System < Subsystem < Component (개요 문서 §6.1)
consists_of(acrux2, adcs).      consists_of(acrux2, eps).
consists_of(acrux2, comms).     consists_of(acrux2, obc).
consists_of(acrux2, payload).
consists_of(adcs, magnetorquer).
consists_of(eps, battery_pack). consists_of(eps, thermal_heater).
consists_of(comms, lora_module).consists_of(comms, antenna).
consists_of(obc, atmega_mcu).   consists_of(payload, etp_panel).
§2

질의(Query) — 그림의 일부만 밝아진다

?- consists_of(acrux2, X).를 던지면, Prolog는 전체 그림에서 이 패턴에 맞는 선만 찾아 되짚습니다. 

?- consists_of(acrux2, X).
X = adcs ;
X = eps ;
X = comms ;
X = obc ;
X = payload.

2단계 화살표 5개만 매칭되고, 그 아래 컴포넌트 층은 이 질의와 무관합니다. 질의 하나가 그래프 전체를 훑는 게 아니라, 패턴에 맞는 부분만 정확히 밝힌다는 걸 그림으로 보면 확실히 느껴집니다.

§3

규칙과 단일화 — 두 사실을 이어붙이기

규칙은 사실 두 개(또는 그 이상)를 변수로 이어붙여 새로운 관계를 만듭니다. 

% 두 단계 아래(System → Subsystem → Component)
assembly(X, Z) :- consists_of(X, Y), consists_of(Y, Z).

% 같은 상위요소를 공유하는 컴포넌트끼리
sibling_component(X, Y) :- consists_of(P, X), consists_of(P, Y), X \= Y.

?- assembly(acrux2, battery_pack).
true.
?- sibling_component(battery_pack, X).
X = thermal_heater.

assembly/2는 acrux2 → eps → battery_pack 두 선을 중간변수 Y(= eps)로 이어붙여 참이 됩니다. sibling_component/2는 battery_pack과 thermal_heater가 eps라는 같은 상위요소를 공유한다는 걸 발견합니다 — 아래 그림의 점선 곡선이 바로 이 "형제" 관계입니다.

§4

재귀(Recursion) — 그림 전체가 규칙 두 줄로

지금까지는 한두 단계였지만, 재귀는 깊이에 상관없이 그림 전체를 훑습니다. 

% 기저(base): 직접 구성요소면
contains(X, Y) :- consists_of(X, Y).
% 재귀(recursive): 한 단계 더 들어가서
contains(X, Y) :- consists_of(X, Z), contains(Z, Y).

?- contains(acrux2, X).
X = adcs ; X = eps ; X = comms ; X = obc ; X = payload ;
X = magnetorquer ; X = battery_pack ; X = thermal_heater ;
X = lora_module ; X = antenna ; X = atmega_mcu ; X = etp_panel.

서브시스템 5개와 컴포넌트 7개, 총 12개가 전부 나옵니다. 규칙은 여전히 2줄인데 그림 전체가 밝아지는 이유는, 두 번째 절이 스스로를 다시 부르면서 한 단계씩 내려가기 때문입니다 — Part-pair 레벨이 나중에 한 층 더 깊어져도 이 두 줄은 고칠 필요가 없습니다.

§5

음성 실패(Negation) — 연결이 없다는 것도 그림이 된다

\+는 "경로가 없음을 확인했다"이지 "관계없다고 증명했다"가 아닙니다. 두 경우를 나란히 놓고 비교합니다. 

independent(X, Y) :-
    component(X), component(Y), X \= Y,
    \+ contains(X, Y), \+ contains(Y, X).

?- independent(antenna, battery_pack).
true.
?- independent(acrux2, antenna).
false.
antenna와 battery_pack이 "무관하다"는 게 아니라 — 실제로는 둘 다 acrux2 밑에서 같은 전력예산을 나눠 쓰는 사이죠 — 이 트리 하나만 놓고 보면 서로를 포함하는 관계가 아니라는 뜻입니다. 지난 대화에서 나온 "COMMS·Payload는 요구사항이 없어서 착시로 ready가 뜬다"는 함정과 같은 종류의 주의사항이에요 — Prolog는 지금 갖고 있는 사실 안에서만 답합니다.
